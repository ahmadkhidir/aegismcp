# C-021: POST /api/v1/emergency/release

**Status:** Frozen
**Owner:** services/gateway
**Auth:** Console administrator or platform operator authenticated through the enterprise identity provider with an OIDC access token in the `Authorization` header, holding the `admin` or `operator` role. A `global` release additionally requires a multi-factor re-confirmation of the initiating operator completed within the preceding five minutes, and in an Enterprise production deployment it also requires a distinct confirming second operator. The deployment identifies itself as an Enterprise production deployment through its configuration; the request carries no deployment or tier selector.
**Request:** Object with:
- `targetType`: string, required, one of `session`, `agent`, `server`, `global`, naming the kind of emergency control to lift.
- `targetId`: string, the session identifier, agent identity, or upstream MCP server identifier whose quarantine is released. Required for `session`, `agent`, and `server`; must be absent for `global`.
- `reason`: string, required and non-blank, the operator's justification, sealed in the ledger with the release.
- `secondApprover`: string, optional, the subject of a different `operator` or `admin` with an active authenticated session who has confirmed the release. Required on a `global` release in an Enterprise production deployment and permitted only there.
**Response 200:** Object with `status` exactly `RELEASED` for a `session`, `agent`, or `server` target or exactly `LOCKDOWN_LIFTED` for a `global` target, and `timestamp` ISO-8601 date-time. The target may connect and invoke tools again before the response is returned. The release is sealed in the shared ledger chain as an administrative audit entry (`action` `release`) naming the initiating operator as `actor`, the supplied `secondApprover` or null, the target type and identifier or the global scope, the outcome, the operator's reason, and the seal timestamp.
**Errors:**
- 400: `targetType` is not one of the four declared values, `targetId` is missing for a scoped target, `targetId` is supplied with `global`, or `reason` is missing, empty, or whitespace only; an Enterprise production `global` release carries no `secondApprover` or carries a `secondApprover` identical to the initiating operator; or a `secondApprover` is supplied for anything other than an Enterprise production `global` target. The target's state is unchanged.
- 401: The access token is missing, expired, or invalid.
- 403: The authenticated operator holds neither the `admin` nor the `operator` role; the `global` multi-factor re-confirmation is absent or older than five minutes; or the supplied `secondApprover` does not resolve to an active authenticated operator session, holds neither `operator` nor `admin`, or has not confirmed the action. An active lockdown stays in force.
- 404: `targetId` carries no active quarantine or lockdown, or a `global` release arrives while no lockdown is in force. The target's state is unchanged.

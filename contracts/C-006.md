# C-006: POST /api/v1/policies

**Status:** Frozen
**Owner:** services/gateway
**Auth:** Console administrator holding the `admin` role, or a CI/CD service account authenticated through the enterprise identity provider with an OIDC access token that carries the `admin` role.
**Request:** Object with:
- `name`: string, required, the descriptive policy title.
- `version`: string, required, the semantic version of this policy configuration.
- `rawYaml`: string, required, the complete declarative YAML policy text.
- `gitCommitHash`: string, optional, the Git commit that introduced the version in the policy repository.
**Response 201:** Object with `id` string, `name` string, `version` string, `status` exactly `draft`, and `createdAt` ISO-8601 date-time. The version is stored, is readable through C-005, and never governs traffic. Publication is available in both deployment modes; activation follows the path the deployment configuration selects: a managed deployment activates the published version through C-018, and a GitOps-managed deployment applies the policy document delivered with the deployment at startup, reloads it on content change without a restart, and records the commit that introduced it, so direct activation is refused there and the console directs the operator to open a pull request. A document identical to a published draft activates that draft record rather than creating a duplicate.
**Errors:**
- 400: The YAML is syntactically invalid, violates the policy schema, or contains an unsupported rule keyword; the previously active policy stays in force.
- 401: The access token is missing, expired, or invalid.
- 403: The authenticated principal does not hold the `admin` role.

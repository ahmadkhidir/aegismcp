# C-018: PUT /api/v1/policies/active

**Status:** Frozen
**Owner:** services/gateway
**Auth:** Console administrator or a CI/CD service account holding the `admin` role, authenticated through the enterprise identity provider with an OIDC access token in the `Authorization` header. The deployment configuration selects the activation path: in a managed deployment this endpoint activates a version, and in a GitOps-managed deployment the policy document delivered with the deployment is the sole activation path — the gateway applies it at startup, reloads it on content change without a restart, and records the commit that introduced it — so direct activation through this endpoint is refused.
**Request:** Object with:
- `version`: string, required, the semantic version to activate.
- `baseVersionId`: string, required, the identifier of the policy version that is currently active and that this activation replaces; an empty string declares that no version is active yet.
- `rawYaml`: string, required, the complete declarative YAML policy text to activate.
**Response 200:** The newly activated policy version as an object with `id` string, `name` string, `version` string, `rawYaml` string, `status` exactly `active`, `gitCommitHash` string or null, and `createdAt` ISO-8601 date-time. A document identical to a published draft activates that draft record and returns its `id` rather than creating a duplicate. The version named by `baseVersionId` transitions to status `archived`, stays readable through C-005 with `status=archived`, and an activation with an empty `baseVersionId` on a fresh deployment archives nothing. The compiled policy replaces the in-memory cache before the response is returned, so a rejected document leaves the previously active version in force. The activation is sealed as an administrative audit entry (`action` `policy_activation`) naming the activating principal, the policy name and version, and the outcome.
**Errors:**
- 400: `baseVersionId` is absent from the body, or the YAML is syntactically invalid, violates the policy schema, or contains an unsupported rule keyword; the previously active policy stays in force.
- 401: The access token is missing, expired, or invalid.
- 403: The authenticated operator does not hold the `admin` role, or the deployment is GitOps-managed and refuses direct activation; the active policy stays in force and the refusal is sealed as an administrative audit entry with outcome `refused`.
- 409: `baseVersionId` no longer names the active version because another activation completed after this client read the active state; the active policy stays in force and no version changes state.
